Slash commands in the prompt: `/fork <task>`, `/delegate <agent> <task>`, `/compact`, `/clear` (asks), `/handoff`, `/ledger <section> <text>`, `/model [@target] [ref]` (no reference opens the Models screen), `/advisor <ref|off>`, `/router <ref|off>`, `/workflow <name> <input>` (also `/fix`, `/build`, `/review`, `/explore` as shorthands when those workflows exist), `/agents`, `/accounts`, `/login [provider]` (no provider opens the provider list; the key is typed into a masked field, never on the line), `/logout <account>` (asks first), `/help`. ## 6. Rendering rules

- Minimum size 80x24. Below 98 columns the advisor rail collapses to a 3-column strip showing the three checkpoint diamonds only (the full rail opens on `a`). Below 100 columns the status bar drops the ledger segment. Below 30 rows the session log shrinks to 3 rows and the fork layer hides its footer.
- The dashboard redraws only when `view:dirty` names one of its widgets, or on resize. Animations (travelling dots, spinner, cursor blink, typewriter) are driven by `Msg::Tick` at 30 Hz, which is only scheduled while `view:animating` is true (any run running, advisor typing, or cursor visible in the prompt). Idle sessions render nothing.
- Unicode: the glyph set is `◆ ◇ ◐ ◓ ◑ ◒ ✓ ✗ » → ▮ █ ▌ ● · ▸ ▾ ◂ ◌`. `[ui] ascii = true` swaps them for ASCII (`*`, `o`, `|`, `/`, `-`, `\`, `ok`, `x`, `>>`, `->`, `#`, `=`, `.`).
- Colours are theme tokens (section 7), never literals in widgets.
- Mouse: on by default, full model in 6.1. Disabled with `[ui] mouse = false` or `--no-mouse`.

### 6.1 Mouse

The UI is meant to be driven by the mouse as well as the keyboard, and every mouse action has a keyboard equivalent, so nothing needs a mouse. Nothing here changes the engine: a mouse event becomes a `Msg::Ui(UiIntent)` and goes through `reduce` like a key press, so replay and tests treat both the same.

- **Hit map.** Every widget registers `HitRegion { rect, id, kind, z }` while it draws. The map is rebuilt each frame inside the 3 ms budget, kept in the TUI crate (not in the graph), and a click resolves to the topmost region at that cell. A modal registers a full-screen backdrop region below its own, so clicks never reach the dashboard behind it.
- **Events.** Press, release, click, double click (400 ms), drag, wheel, move. Move events are only requested while something can react to hover, and they are coalesced to one per frame. The terminal's own selection still works with Shift held.
- **Click.** Focuses a pane. On a run card or row it selects the run. Double click opens the run's transcript (same as Enter). Tabs, status bar segments, ledger segments, breadcrumbs and the `a` rail strip are clickable. Checkpoint diamonds open that checkpoint's advice.
- **Buttons.** The permission modal and every other modal show real buttons (`Allow once`, `Allow always`, `Deny`, `Cancel`) with a hover and a pressed state. Clicking outside a dismissible modal closes it. The permission modal never closes on an outside click, because that would be an unintended deny.
- **Wheel.** Scrolls the pane under the pointer, not the focused one, three lines per notch. Shift plus wheel scrolls sideways where a pane scrolls sideways. Scrolling a transcript away from the bottom pauses auto-follow, and a `jump to latest` button appears.
- **Scrollbars.** Every scrollable pane shows a thumb. Click on the track pages, drag on the thumb scrolls.
- **Resize.** The borders between the rail, the card list and the session log are drag handles (the cursor shape cannot change in a terminal, so the border highlights on hover). Sizes persist in `state/ui.toml` and are clamped by the minimum sizes in section 6.
- **Context menu.** Right click on a run card or row opens a small menu: `Open transcript`, `Cancel`, `Fork`, `Resume`, `Copy id`, `Copy result`, `Status`, `Cost`. Items that do not apply are shown disabled, not hidden.
- **Hover.** The element under the pointer gets the `hover` theme token. After 500 ms still, a tooltip shows what the cell truncated: the full agent name and description, the model and account, the cost, the run id. A tooltip is a layer over the frame, never part of layout.
- **Text.** Dragging in the transcript selects text by cell, double click selects a word, triple click a line. `Ctrl+C` or a click on the `copy` hint copies through OSC 52 and, where the terminal ignores it, the system clipboard crate. `Ctrl+C` with no selection keeps its cancel meaning.
- **Prompt.** Click places the cursor, drag selects, wheel scrolls a long prompt.
- **Drag and drop.** Dragging a file path onto the terminal arrives as pasted text and is treated as a path insert, not a command.
- **Opt-outs.** `[ui] mouse = false`, `--no-mouse`, and automatic off when the terminal reports no mouse support. With the mouse off, hover tooltips and context menus are reachable by keyboard (`Tab` to focus, `m` for the menu, `Space` for the tooltip).
- **Contrast.** Hover, pressed, selected and focus states are theme tokens measured like the rest (4.5:1 for text, 3:1 for borders), listed as constants in the theme tests.
- **Tests.** The hit map is tested by table (point, expected id, with overlapping layers). Interactions are tested by feeding synthetic `MouseEvent` sequences through the event layer into `TestBackend` and asserting both the resulting `Msg`s and the frame, including the hover, pressed, disabled and tooltip states.

## 7. Theme

The recording's palette, sampled: background `#1a1b26`, panel background `#1f2029`, text `#c0caf5`, dim `#565f89`, orange (lead) `#f0a070`, blue (swarm) `#7aa2f7`, green (router) `#9ece6a`, purple (advisor) `#bb9af7`, yellow (permission) `#e0af68`, red (error) `#f7768e`, split-remainder brown `#6b4a3a`, highlight row `#2a2b3d`.

```rust
pub struct Theme {
    pub bg: Color, pub panel: Color, pub fg: Color, pub dim: Color, pub highlight: Color,
    pub lead: Color, pub swarm: Color, pub router: Color, pub advisor: Color,
    pub ok: Color, pub warn: Color, pub error: Color, pub split: Color, pub split_rest: Color,
}
```

Three built-in themes: `recording` (above), `light` (WCAG AA checked: fg on bg at least 4.5:1 for text, 3:1 for bars and borders; the ratios are listed in `aibus-tui/src/theme.rs` tests and asserted), and `mono` (no colour, for `NO_COLOR` and dumb terminals). `[ui] theme = "recording"` selects; `NO_COLOR` forces `mono`; `COLORTERM=truecolor` enables the hex values, otherwise the nearest 256-colour index is used.

## 8. Ambiguities and the defaults I picked

| Ambiguity | Default |
|---|---|
| The recording's cards loop from done back to running. | Cards stay done; the loop is demo behaviour. |
| Whether the fork counter is per session or lifetime. | Per session; the status bar segment resets on `/clear`. |
