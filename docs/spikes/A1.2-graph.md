# A1.2 spike: the Graph trait and the mini engine

D-02 bet that the mini engine fits in a week and under 1,500 lines. I wanted to find out, so I wrote it start to finish and kept notes on what fought back.

## Numbers

- `src/mini/`: 625 lines (`mod.rs` 389, `engine.rs` 236), against the 1,500 budget. The contract types and trait are another 313 lines in `src/lib.rs` and `src/types.rs`.
- Tests and bench: about 1,000 lines (the conformance suite is 800 of them, and most of that is the suite itself, not scaffolding).
- Time: about 7 minutes of wall clock between the first read of the spec and the green gates (10:40 to 10:47 UTC by `date`), almost all of it in one pass. That is a very different number from "a week", but it counts a design I had already half made while reading section 4, and none of the review, fuzz or differential work that will follow. I would not plan on it for the causl host layer.
- Recompute micro-bench (300 nodes, one write reaching 10 deriveds, release build, 20,000 commits): p50 2.3 us, p99 3.4 us, mean 2.4 us, against the 50 us soft budget. That is the whole `commit`, including the history append.
- 4,096 retained commits, each rewriting 8 handle inputs and recomputing 8 deriveds: 3,866,624 bytes live (about 944 bytes a commit), 3,956,672 after another 8,192 commits with eviction running. That is under 4 MiB, but only by about 8 percent for such a busy commit. The cost is roughly 40 bytes per changed node plus about 160 per commit, so the "tens of bytes per changed node" line in spec 03 section 9 holds, and a session that changes more than about 16 nodes on every commit would break the 4 MiB claim.

## What I changed or added to the section 4 signatures

- `Tracker::get` and `get_key` return `&'a Value` (the lifetime of the graph borrow), not a reference tied to `&mut self`. With the signature as written you cannot hold two reads at once, so `t.get(a) + t.get(b)` over references does not compile. Every caller of the original form still compiles.
- `Tracker::fail(msg)` is new. The spec says compute is pure and cannot error, but it also demands "an error inside a commit leaves the graph byte-identical", and `Compute` returns a bare `Value`. Without an error channel the atomicity rule cannot be tested. `fail` records the message, returns `Null`, and the commit rolls back with `CommitError::Compute`. `Tracker::commit()` is also new, so commit-metadata deriveds can see the commit being built.
- `Tracker::new` takes a `&HashMap<NodeKey, Node>` for `get_key`. A closure there ran into a lifetime knot with the value reader, and the causl backend will have its own key map anyway.
- `Unsubscribe` is a flag handle (`Arc<AtomicBool>`) with `unsubscribe(self)`. The observer is dropped at the next commit.
- The spec names `SimulateResult`, `Explanation`, `RetentionResult`, `HydrateError` without defining them. I made `SimulateResult::Applied { time, changed } | Rejected(CommitError)`, `RetentionResult::Found | Evicted { oldest_retained } | Future { now }`, and an `Explanation` that is flat (direct dependencies plus every transitive input) rather than a tree, so a diamond ladder cannot blow it up.

## What was awkward

1. **"One commit creates exactly one time or zero."** I read "zero" as: a commit that changes nothing creates no time, no log entry and no subscriber firing (writing the current value is cut off at the edge). `hydrate` is the exception, it always adds one. If `reduce` ever depends on every `Msg` landing in the log, it needs a write that always changes (`model:last_msg` does that already).
2. **Kahn plus dynamic dependencies.** Kahn needs the edges up front, but edges are discovered by running compute. I order the affected set with the edges from the previous commit and let a compute that reads a node still pending block; that node is settled first and the compute retried. It is 20 lines, and a cycle surfaces as `CommitError::Cycle`. A derived is only recomputed when one of its old dependencies actually changed, which is the cutoff.
3. **Commit-metadata deriveds.** They have to run after everything else, because `changed_nodes` is not known earlier, so a normal derived cannot depend on one. The engine only catches that when the reader recomputes for some other reason (then `MetadataDependency`); otherwise the reader stays stale. The spec should say metadata deriveds are sinks. `view:dirty` is one, so this works for the stated use.
4. **`commit_log() -> &[Commit]` against a bounded ring.** A `VecDeque` cannot hand out one slice. I keep a plain `Vec` with a start offset and drop the evicted prefix in batches of 512, growing it in exact steps, otherwise doubling holds twice the window and the memory test fails.
5. **Retention needs a baseline.** To answer `read_at(t)` after eviction I keep per-node `base` values, the state at the oldest retained time, and fold evicted commits into it. `oldest_retained` is that base time, so with 4,096 retained commits the oldest readable time is `now - 4096`.
6. **`F64` and `PartialEq`.** The derived equality makes `NaN != NaN`, so a derived that yields `NaN` is never cut off and fires every commit. Nothing in aibus produces one on purpose, but the Value spec should either forbid it or compare bits.
7. **Registration is outside time.** `input` and `derived` do not advance `now`, so a node registered at time T answers reads before T with its first value. Fine for startup, worth knowing for the causl backend.
8. **Duplicate keys.** The first registration wins and later ones return the same node. I would rather have an error, but `input` and `derived` return a bare `Node` per the spec.
9. **Dependency pins.** MSRV 1.85 forced `smol_str` 0.3.2 (0.3.0, 0.3.1 and 0.3.3 fail `cargo deny check advisories`, 0.3.0 for sure as yanked, and 0.3.4 and later need rustc 1.89) and `proptest` 1.11 (1.12 needs 1.88). They are pinned in `Cargo.lock`, not in the manifest, so a plain `cargo update` can break the build until the MSRV moves.

## What went smoothly

Staging the whole commit before touching the graph made atomic rollback free: there is nothing to undo, and `simulate` and `hydrate` share the same function as `commit`. Making tracked reads the only reads (the `Tracker`) also kept `compute` honest without any runtime checks. I checked the suite bites by breaking the engine four ways (no cutoff, stale dependency lists, no duplicate-write check, no metadata pass), and each one failed it.
