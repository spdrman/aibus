# A1.5 spike: causl-engine-core feasibility (blocked)

Status: blocked on 2026-11-08. I could not obtain `causl-engine-core` from a source that another machine can fetch, so I did not write the host layer, did not run the conformance suite against it, and did not repeat the A1.3 stream-commit measurement. Issue #7 stays open as the blocker for C2.4. The `mini` engine carries on unaffected, and the default feature set is untouched (this PR adds no code and no `causl-rs` feature).

## What I tried

1. **Public mirror, `sheetbaseproject/causl-engine-core`.** I looked at it on 2026-11-08. It is public and MIT, but it holds one commit (`da13f48`, "Bootstrap the repo with a README and licence") and two files, `LICENSE` and `README.md`. The repo description says it is "populated from the upstream release branch by the maintainer", and that has not happened yet. No source to depend on.
2. **Private Gitea, `https://git.opsite.ca/causl/causl-core-rs.git`.** This is the real primary (crate `causl-engine-core` under `tools/engine-rs-core`). `git ls-remote` with the default credential helper works on my machine, but with the helper disabled and prompts off it fails with "could not read Username". So it needs a token, which nobody else building this repo has, and I will not put one in `Cargo.toml`, `deny.toml` or the lockfile.
3. **Local checkout** under `/Users/rom/workspace/causl/` (`causl-core-rs` and its worktrees). I only used it to find the commit a pin would point at. The `chore/512-merge-back` branch that spec 03 section 2 was written against is at `a6247b36b38dda4d97017d0577210aa8c724e4f2`. A path dependency on a checkout is no use to anyone else, so none of it is in this repo.

## Why I did not commit a git dependency on Gitea anyway

Cargo resolves optional dependencies into `Cargo.lock` and fetches every git source to verify it, even when the feature is off. So a pinned Gitea git dependency would make `cargo build --workspace --locked` (and `cargo deny check`, which needs `allow-git` for that remote) fail for everyone without Gitea credentials, default features included. That breaks the one rule this spike must keep: the default build never touches `causl-rs`. The same applies to vendoring the private source into this repo, which I did not do and which is the owner's call, not mine.

## What the unimplemented backend traits would cost

I have not verified this against a build. From the read in spec 03 section 2: `Persister`, `Reader` and `Observable` are `unimplemented!()` placeholders, so the host layer would have to cover `snapshot`/`hydrate` through serde on `State`, reads through `State::get_value` and `read_at`, and subscriptions through `register_subscriber` with a `SubscriberCallback`. That is plausible, but the hydrate-advances-time rule and the byte-identical differential snapshot are exactly what I cannot vouch for without running them.

When the crate is available, the work is the one described in issue #7, and I would budget it by the A1.2 note: do not extrapolate from the 7 minute mini build.
