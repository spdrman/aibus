# B1.2: tools, policy, permission modes and bash

Notes for whoever builds on the tool layer next (B1.3 hooks, B2.1, C2.1). I kept it to what is not obvious from the code.

## How a call flows

`ToolExecutor::call_gated(eff, cx, mode, name, input, ask)` is the only way the run loop runs a tool now. In order:

1. the name has to be in the effective allow-list (A2.2, unchanged);
2. `bash` is split into simple commands (`tools/shell.rs`) and each part is checked against `tools/shell_deny.txt` plus `[tools] deny_patterns`, then against the deny specifiers, then against the allow patterns, where every part has to be covered;
3. `write` and `edit` paths are resolved even when the file does not exist yet, and the `.git/**`, `.aibus/settings.toml` and `~/.config/aibus/**` deny-list is applied (a specifier that names the path lifts it, nothing else does, `bypass` included);
4. `permission::decide(mode, tool, need, pre_approved)` gives `Allow`, `Ask` or `Deny`; on `Ask` the `ask` closure runs and its answer decides;
5. the tool runs, and its output is capped to the tail.

`ToolExecutor::new` builds an executor with no pre-approved patterns and no terminal, which is what the A2.2 tests use. `ToolExecutor::with_gate` takes the `Gate` (pre-approved patterns, extra deny patterns, tty, redactor, home).

## The bash splitter

`split` is deliberately paranoid. It splits on `;`, `&`, `&&`, `|`, `||`, `|&` and newlines, descends into `( )`, `$( )`, backticks and `<( )`/`>( )`, and refuses (so the call is denied, even for a bare `bash` allow) when it cannot be sure: unterminated quotes or brackets, heredocs, `$((...))`, `$'...'`, nested backticks, a command word that is an expansion, assignments to `PATH`/`LD_PRELOAD`/`IFS` and friends, an assignment that holds a substitution, and any whitespace the shell does not treat as a blank. Quoted separators stay inside their word. The table tests in `tools/shell.rs` and `tests/bash.rs` are the contract, so add a row there before changing a rule.

The cost is false refusals (`if ...; then ...; fi` under `bash(git *)`, for instance). I preferred that to a hole.

## Run loop

`RunMail::Permission` is handled now: `PermissionNeeded` (with the agent) goes out, the run waits, `PermissionDecided` follows. With no terminal (`Gate::tty == false`) the run answers itself with `Deny` and reason `no tty`. `ask_user` parks the run in `WaitingUser` (the reducer does that on the `ToolCallRequested` for it) and the next `RunMail::UserMessage` is the tool result. `enter_plan_mode` and `exit_plan_mode` change the loop's local mode only, so the definition's mode comes back on exit.

## Things I did not do

* `[hooks] pass_env`: `Bash::new` takes the list, but the config has no such key yet (hooks are a map of event to hooks), so `aibus run` passes an empty list. B1.3 owns that.
* `web_fetch` and `delegate` are not tools yet; their cells of the 09 table are covered by `decide` with `Need::Ask` only.
* No OS sandbox (09 section 2): a started command has the user's rights.
