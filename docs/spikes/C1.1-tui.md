# C1.1: the TUI shell, theme, key map and mouse

Notes for whoever builds on the dashboard next (C1.2 and the screens after it). Only what is not obvious from the code.

## What is where

- `layout.rs`: the 05 section 6 rules (`areas`), the two draggable borders and `state/ui.toml`. `Layout { rail, log }` holds the dragged sizes, `None` is automatic. Under 98 columns the rail is a 3-column strip and `a` draws the full 22-column rail over it (no re-layout), under 100 columns there is no ledger segment, under 30 rows the log has 3 rows and the fork layer loses its footer, and under 80x24 the frame is the message `terminal too small`.
- `theme.rs`: `recording`, `light` and `mono`, the `hover`, `pressed`, `selected` and `focus` tokens, `Theme::resolve` (`NO_COLOR`, `COLORTERM`, `[ui] ascii`) and `nearest_256`. `tests/theme_contrast.rs` pins every measured ratio in a named table.
- `glyphs.rs`: the spec glyph set with its ASCII table, `Theme::g` for the glyphs whose substitute is wider than one cell (`ok`, `>>`, `->`), and a sweep over the finished frame for everything else (borders, partial blocks).
- `keys.rs`: every binding of 05 section 4, `[keys]` and `keys.toml` overrides by action name, conflict warnings, and the rows `?` is drawn from.
- `hit.rs`, `input.rs`: the hit map and the event layer. `Input::mouse` and `Input::key` take a crossterm event plus the last frame's `Drawn` and return `Msg`s; nothing in them touches a terminal, which is how the tests drive them.
- `ui.rs`: `render` draws a `Scene` and returns `Drawn` (hit map, areas, log extent, card count). `Ui::draw` also redraws when the `ctrl:` state, the pointer or the prompt changed, not only on `view:dirty`.
- `aibus/src/tui.rs`: `aibus` on a terminal with no subcommand runs startup steps 1 to 7 and then `aibus_tui::app::run`.

## Core changes

- `Msg::Ui(UiIntent)` (focus, focus next and previous, select, scroll, open, toggle rail, set rail width, set log rows). `reduce` handles it with the same code as the matching `Command`s. `Msg::Mouse` stays but the TUI no longer sends it.
- Three new `ctrl:` inputs: `ctrl:rail:expanded`, `ctrl:layout` and `ctrl:scroll:cards:x`. They are part of the graph hash, so `tests/replay/explore-fake/snapshot.hash` changed (`f623706b027c8358` to `c4193504b533425a`); nothing else in the recording did.
- `Select(Cards, ...)` also moves the 3-card window so the selection stays visible. The log cannot be scrolled past its oldest row.

## Deviations and judgment calls

- **The ledger segment now shows from 100 columns.** The issue and 05 section 6 say 100, 05 section 2.9 says 110. I followed section 6.
- **Spec lists 13 ASCII substitutes for 19 glyphs.** The six it leaves out (`▌ ● · ▸ ▾ ◂ ◌`) became `_ @ . > v < :`. Box drawing, partial blocks and the legend square are swapped by the sweep (`+ - |`, `- =`, `#`).
- **`a` opens the rail but does not close it.** On the open rail `a` just keeps the focus there. A click on the strip toggles it. Tell me if you want `a` to toggle.
- **Mouse auto-off is by `$TERM`.** A terminal with `TERM=dumb`, `linux` or empty gets no mouse. There is no live capability query (DECRQM) because it needs a read from the tty with a timeout and I could not test it here.
- **Move events are asked for with `?1003h` only while a hoverable region is on screen** (always, on the dashboard; not behind a modal). Presses, drags and the wheel use `?1000h ?1002h ?1006h`. Bursts of moves and drags in one batch collapse to the last (`input::coalesce`), so hover costs one pass per loop turn.
- **Hover and pressed state are not in the graph.** They change with every move; the hit map is not in the graph either (the spec says so). A click and a key take the same path (`Msg::Ui`), which is what replay needs.
- **Scrollbar on the session log only.** It is the only scrollable pane today. The thumb sits on the log's right border, clicking the track pages by the visible rows, dragging the thumb sets the scroll from its position.
- **Not built: buttons, right-click menu, tooltips, text selection.** They are in 05 section 6.1 but not in the issue's list. The permission modal does not exist yet (C1.2), so the backdrop rule is tested with a poked `permission` modal name.
- **Modals that have no screen yet** draw a small `this screen is not built yet` box; `advice` shows the last advice from the rail view.
- **The prompt is a plain line**: type, Backspace, Esc clears, Enter sends `Msg::SubmitPrompt`. `aibus "text"` on a terminal puts the text in the prompt without sending it. Nothing starts the lead run from a TUI session yet, so a sent prompt only reaches the reducer.
- **`LOG_LINES_KEPT` went from 24 to 128** so the log has something to scroll. The A2.5 render bench was not rerun.
- **`Ctrl+c`** cancels the selected card's run, and the second press within 2 s quits (the loop already did that).

## Not verified

- No real terminal: the raw mode, alternate screen and mouse escape sequences have only unit tests on the strings (`mouse_switch`), nothing ran on a tty. Windows Terminal (Q21) was not tried.
- The `aibus` wiring is covered by the `options` tests; `run` itself was never started.
