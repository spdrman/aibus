# C1.3: transcript, modals, screens and the mouse

Notes for whoever builds on this next (C2.x). Only what is not obvious from the code.

## What is where

* `aibus-core/src/state/store.rs`: a transcript is now a list of chunks, sealed text blocks and events (a user message, a tool call with its result, a compaction, a note). The wrapped-line cache is still per sealed block, so a stream commit wraps the tail only (`Store::wrap_calls` is what the test counts). `Store::transcript_rows` returns a window of rows at one width. Each tail version has a mark with the text length at that point, which is what lets a view be cut back to an earlier version.
* `aibus-core/src/state/reduce.rs`: records the events (`ToolCallRequested`, `ToolCallFinished`, `Compacted`, `RunFailed`, the prompt at `RunStarted`, `SendMessage`), owns `ctrl:transcript` (follow, top row, selected call, expanded calls, time travel) and opens the permission modal on `PermissionNeeded`. `ctrl:modal` is still the single source of truth; a prompt that covers another modal remembers it in `ctrl:modal:under` and gives it back.
* `aibus-core/src/persist/transcript.rs`: `reload` reads `transcript.jsonl` back into a store entry a chunk of lines at a time.
* `aibus-tui/src/views.rs`: `view:permission`, `view:palette`, `view:agents`, `view:accounts` and `view:transcript` (header plus the rows that fit, already wrapped). `view:transcript:<run>:lines` is a store handle registered when a transcript opens (`view::ensure_lines`).
* `aibus-tui/src/prompt.rs`: the prompt line as plain data (cursor, selection, history, completion, slash commands). It is not in the graph.
* `aibus-tui/src/screens.rs`, `transcript.rs`: the drawing. `input.rs` holds the keys and the mouse. Every screen action goes through `Input::screen` or `Input::act` whether it came from a key or a button, so the two cannot drift.
* `aibus-tui/src/app.rs`: the loop. New: bracketed paste, OSC 52 plus the system clipboard, jobs (open `$EDITOR`, new agent template, validate, account operations), reading a finished run back from disk on a blocking thread, the session writer.

## Deviations and judgment calls

* **No `cargo insta`.** The repo already had its own text snapshot checker from C1.1; `docs/TESTING.md` describes the same workflow with it.
* **`e` in the permission modal denies and sends the edited line.** Replacing the input of the call that is waiting needs `call_gated` to take the input after the question, which is a run-loop change. Until then `e` denies this call and messages the run "Run this instead: ...", which makes it propose the edited call again.
* **Time travel is for the transcript.** `[` and `]` step to the previous or next commit that changed the run's transcript (`read_at`), and past the retained window the view says `evicted, oldest retained t=...` (`snapshot_at`). Stepping the whole dashboard through history is not done: the dashboard's derived views are computed from the live graph, not from a snapshot.
* **The permission modal shows the gate's one line.** The gate gives the tool name and a redacted summary, not the working directory, timeout or the hook verdict that 05 section 5 sketches. The modal shows the prompt's `cwd` and the summary.
* **The alert is shown first.** With a prompt waiting, the status bar tightens the gaps between segments so `! N permission waiting (p)` fits at 98 columns. At 80 columns it still does not fit; the modal itself is the signal there.
* **The cursor blinks from the tick counter, so ticks run while the prompt has focus** (05 section 6 says the cursor counts as animating). `Ui::animating` is false when only the cursor is moving, and then a frame is drawn only when the blink phase changes.
* **Palette workflows.** No workflow registry exists yet, so the palette lists commands, agents and runs, and the `/fix`, `/build`, `/review`, `/explore` shorthands complete only when a workflow of that name is passed in (nothing passes one yet).
* **Account `enabled` is not in the graph,** so the accounts screen shows `ready` or `no key`, not `disabled`.
* **Wheel on the prompt moves the cursor a row,** and the view follows the cursor.
* **A tool's result is shown unredacted** in the live view (the persisted transcript is redacted). The result is cut to 4 KiB in memory and 12 rows when a call is expanded.

## Inherited from C1.2

* Permission prompts are no longer refused as "no tty" in a TUI session: the gate gets `tty: true` when the session is interactive, and `aibus/src/tui.rs` hands answers to the run's mailbox. The alert in the status bar opens the modal.
* The session writer now runs for TUI sessions (`msgs.jsonl`, the commit log, each run's `transcript.jsonl`), which is also what makes a finished run's transcript readable later.
* Not done: `session_start` and `session_end` hooks for TUI sessions, and an unbuildable lead still fails as a run in the log (with `r` to retry from its transcript) instead of exiting 4. The accounts screen is how you fix it in the session, so I left that as it is.
* Not done: the lead of a TUI session still gets neither the handoff nor the ledger text, and no learnings are extracted at the end (C1.4 left these).

## Not verified
