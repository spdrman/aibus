# C2.1: security hardening

Notes for whoever builds on this next (C2.5, and anyone adding a tool or a writer). Only what is not obvious from the code. The threat table with its tests is `docs/SECURITY.md`.

## Tests that watch every other test

* `xdg_temp()` (the C2.2 helper, see docs/TESTING.md) is the temp directory of every integration test of `aibus` and `aibus-core`; it is `Deref` to `tempfile::TempDir`, so `.path()` still works. When it is dropped and the test has not failed, it greps the whole tree for the fake key (raw and base64, `.zst` files unpacked) and fails the test if it finds it. It also starts a `capture_logs()` for the test unless one is already running, so the log grep of 10 section 3 is on for every test that makes a directory. A test that wants a file with the fake key in it on purpose has to build its directory with `tempfile` directly... there is none today.
* `LogCapture` keeps its forbidden list itself now (it used to live only in the thread's slot), so two captures on one thread (the one `xdg_temp` starts and the test's own) each check their own buffer, and the older one does not clear the newer one's slot when it drops.
* `aibus-core` has both provider crates as dev-dependencies now, linked into `tests/security`, so their debug logs are part of what the grep sees. That does not touch the boundary tests in `aibus-testkit/tests/workspace.rs`, which look at normal dependencies only.

## Fuzzing

* The bodies of the four targets are in `fuzz/checks.rs`, and `crates/aibus-core/tests/security/fuzz.rs` pulls the file in with `#[path]`, so what the fuzzer asserts is exactly what a push replays. Add an invariant there and it is on in both.
* The tool-pattern target needed `tools::split`, `normalise_command` and `spec_matches` to be `pub`; they are re-exported from `aibus_core::tools` and that is all that changed about them.
* The first thing it found was a panic in `ShellDeny::hit`: the suffix after a space was cut at `i + 1`, which is inside a two-byte space such as U+00A0. A model could have crashed the process with `git\u{a0}status`. Fixed with `c.len_utf8()`; the input is `fixtures/fuzz/tool_pattern/deny-hit-slices-inside-a-multibyte-space` and `deny_hit_survives_multibyte_whitespace` is the unit test.
* `fuzz/Cargo.lock` is the root lock plus `libfuzzer-sys`. When the root lock moves, copy it again and let cargo add the fuzz crate back, or the fuzz workspace drifts off the MSRV pins.

## Redaction

Three patterns are new (`openai-project-key`, `google-api-key`, `api-key-field`), each from a body in `fixtures/redact/provider-errors.toml`. `api-key-field` is the greedy one: it eats the value after `api_key=`, `x-api-key:` and the like, anything of 8 or more characters from `[A-Za-z0-9._~+/=-]`. If it ever eats something that matters, add the line to the negative corpus in `tests/redact.rs` and narrow the value class.

## The sandbox

* `[tools] sandbox = "none" | "bwrap" | "sandbox-exec"` and `sandbox_network` (default true). The issue says `sandbox.network`, but a key cannot be a string and a table at once, so the switch is a sibling key.
* Only `bash` goes through it (`tools/sandbox.rs`, wired by `Bash::with_sandbox`). Hooks, gates and MCP servers are commands the user wrote and still run as before.
* The command is built in one place (`Bash::command`), including the `exec 2>&1` prefix, and `exec` takes the finished `std::process::Command`. A configured kind whose program is not on `PATH` refuses the call (`ToolError::Denied`), it never falls back.
* `bwrap` gets `--unshare-user-try` because as real root in a container (no user namespace of its own) `--unshare-net` fails with `loopback: Failed RTM_NEWADDR`. On a normal desktop user the flag changes nothing.
* The `bwrap` test needs the program and a kernel that lets it make a namespace. A plain container does not, so the test skips with a message unless `AIBUS_REQUIRE_SANDBOX=1`. I ran it on MARS with `--cap-add SYS_ADMIN --security-opt seccomp=unconfined --security-opt apparmor=unconfined`.
* The `sandbox-exec` profile (`PROFILE` in `tools/sandbox.rs`) is `allow default`, deny all file writes except the project, the working directory, `$TMPDIR` and a few device nodes, deny reads under `/Users`, `/Volumes` and `$HOME` except those same three. I did not run it (nothing runs on a host here). It is a deny-list on reads, so it is weaker than the `bwrap` mount view: system paths outside `/Users` stay readable.

## Not done

* `aibus doctor` checks that the program is on `PATH`, it does not start it (a probe would be `bwrap --ro-bind / / true`, which fails inside most containers for reasons that say nothing about the user's machine).
* `isolation: worktree` still refuses to start (B2.1), so "the project (or worktree)" is the run's working directory plus the project root; a git worktree outside the project needs both, and both are bound.
* No `http` or `prompt` hook output goes through the `[hook <name>]` label test; they share the code path with command hooks.
