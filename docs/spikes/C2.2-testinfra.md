# C2.2: test infrastructure, integration suite and replay fixtures

Notes for whoever builds on this next (C2.4 above all). Only what is not obvious from the code.
`docs/TESTING.md` has the how-to; this is the why and the loose ends.

## What is where

* `aibus-testkit`: `xdg_temp()` / `Xdg` (`src/session.rs`), `big_session(mk)` (same file), the replay harness (`src/replay.rs`), plus what C1.1 to C1.3 already had (`FakeClock`, `capture_logs`, `tui::render`, `assert_frame!`, `assert_styles!`).
* `aibus-core/tests/integration/`: one test per bullet of 10 section 4 (16 tests, the concurrency cap has a graph-level one and a lead-level one). `rig.rs` is the delegation/lifecycle rig, copied from the two test files that each had their own, `solo.rs` is one lead run. The older per-feature test files stay as they are; they test the pieces, this suite tests the named scenarios.
* `tests/replay/`: 22 fixtures with `msgs.jsonl`, `script.ron`, `snapshot.hash` and `views.json`, from `tools/record-replay.sh`.
* `aibus_core::replay`: the codec now covers `UsageUpdate`, `PermissionNeeded`, `PermissionDecided`, `HookFired`, `RouterAnswered`, `AdvisorSpoke`, `CheckpointHit` and `Compacted` besides the six it had, and exports `replay_into` (steps a stream into an app the caller built) and `snapshot_hash`.
* `aibus_tui::replay_views`: the `view:` nodes after a replay with the dashboard registered. `aibus run --record` calls it to write `views.json`, and the testkit calls it to check them, so the two cannot drift.

## Judgment calls

* **`views.json` is a fourth file.** The spec lists three; item 3 of 10 section 5 ("every `view:` node at the end equals the recorded one") needs something recorded to compare with, and the hash only covers inputs.
* **`explore-fake` was re-recorded.** It had no `UsageUpdate` and no `views.json`. The new stream has `UsageUpdate` after each stream message, so its hash changed and `aibus-core/tests/replay.rs` expects the longer sequence.
* **The integration suite is mini-only.** `common::app()` builds a `MiniGraph`. Making `Rig` and `Solo` generic was a lot of churn for cases that only use `App::step`, and the second backend is covered by conformance and replay.
* **`session_end` is stitched together in the test.** The binary's `continuity::end` is private to the `aibus` crate, so `integration/continuity.rs` calls the same core functions in the same order (handoff, extract, append, index, recall) and `continuity_cli.rs` stays the end-to-end check on the binary.
* **Exit mapping 5 is asserted through `AibusError`.** The run's error is `RunErrorKind::Provider`, and `AibusError::Provider` is exit 5; the CLI's own test (`exit_codes.rs`) drives the binary.
* **Recorded `HandoffWritten`.** The session code steps it into the app directly, so a recorded stream has none (compaction's auto-handoff goes through the loop but the headless run has no handoff sink, so none there either). The codec handles the message; no fixture contains it.
* **Real time in the recorder.** `retry-after-429` waits a real second because it records through the binary. The other fixtures are instant.
* **No `insta`.** Same call as C1.3; the frame checker stays.
* **Workflows.** `ci.yml` is one job per layer row, `nightly.yml` is new (live providers, fuzz), `bench.yml` gets the nightly and path triggers. None of it has run: the repository uses local gates now, and the fuzz job is a no-op until `fuzz/` exists (C2.1).
