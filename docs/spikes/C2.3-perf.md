# C2.3: performance gates, baselines and the memory budget

Notes for whoever builds on this next (C2.5). Only what is not obvious from the code.

## What is where

* `benches/gate.rs` (repo root): the p99 gate every bench includes with `#[path]` (std only, so the causl crate can include it too). `Gate::best_of` keeps the lowest-p99 round of three, `judge` checks the budget and the baseline, `finish` exits non-zero when `AIBUS_BENCH_GATE=1` and anything missed. `AIBUS_BENCH_SAVE=1` writes the baseline, `AIBUS_RUNNER_CLASS` picks `benches/baselines/<class>/`.
* `aibus-core/benches/commit_stream.rs` + `shared/{fixture,stream}.rs`: the reference session (`fixture::big_session`) and the measurement. `aibus-graph-causl/benches/commit_stream.rs` includes the same files and runs it on `causl`.
* `aibus-core/benches/hydrate_snapshot.rs`, `aibus-tui/benches/render_dashboard.rs`.
* `aibus-core/tests/long_session.rs` (12 h, 300 runs), `tests/caps.rs`, the mailbox/stream fill test in `tests/run_actor.rs`; `aibus-testkit/tests/startup_time.rs` and `streaming_cpu.rs` (soft, logged).
* `aibus-core/src/mem.rs`: `rss_mib` (moved from `aibus/src/tui.rs`), `numbers` (what `memory.json` holds) and the 10 s sample period. `Store::stats` is the store half of those numbers.
* `.github/workflows/bench.yml`: nightly and on PRs touching `state/`, the graph or the TUI.

## How noise is handled

The benches run on shared machines, so a raw p99 is not comparable across runs. Three things:

* Each measurement runs three rounds and keeps the one with the lowest p99. Load only adds time, so the minimum is the least noisy estimate.
* The baseline stores a `calibration_us` (a fixed hash loop that touches no aibus code). A run scales the baseline by `calibration_now / calibration_then` before applying the 20 %.
* `NOISE_FLOOR_US` (25 us) is added to the allowed value. Today's p99s are tens of microseconds against budgets of milliseconds, and 20 % of 29 us is inside the jitter of a quiet machine.

The absolute budgets (2 ms open stream commit, 4 ms any commit, 3 ms render, 10 ms resize) are not scaled. They are a hundred times above what MARS measured, so a loaded runner does not matter for them.

## Deviations and judgment calls

* **No `criterion`.** The gate needs a per-iteration p99, and criterion reports per-sample means. The causl crate (outside the workspace, private source) also cannot take a new dependency. The benches keep the existing `harness = false` shape and the `AIBUS_BENCH_GATE=1` switch from the spikes.
* **Baselines are for the class `mars`** (a container on MARS). The CI workflow uses the class `github-ubuntu-latest`, which has no baseline yet: there it enforces the budgets only, until someone runs the workflow with `AIBUS_BENCH_SAVE=1` on that runner and commits the files. Actions is off for this repo today, so the workflow has not run.
* **The causl bench was updated but not built or run.** Its source is private and the sandbox has no token; the wrapper only changed the `#[path]` includes.
* **Running runs keep all their sealed blocks.** 08 section 5 says "the open transcript's blocks plus the last 64 KiB tail of every running run". The store keeps every block of a running run and drops them at `RunFinished` (`evict_finished`). Dropping the others needs a signal for which transcript is open and a way to stream a running run's old blocks back from `transcript.jsonl`; neither exists before the transcript screen. `long_session` asserts what does hold: finished runs keep a head of at most 2 KiB and nothing else, and the store never holds more than the running runs streamed plus those heads.
* **Wrapped-line caches are not dropped when a transcript is closed.** There is no close yet; they go on a width change and when the run finishes. The test asserts both of those and that no cache entry outlives its block.
* **The resident number is the whole test process** (`/proc/self/statm`, 4 KiB pages), so `long_session.rs` holds exactly one test. Off Linux it checks the caps and skips the 500 MiB assertion.
* **Model caches under 20 MiB** is asserted on the size of the model tables the provider crates ship. There is no in-memory cache with a measurable size yet (the tables are loaded by the providers, which core cannot see).
* **Hook capture (1 MiB)** was already filled by `tests/hooks.rs`; I did not duplicate it. The bash cap (256 KiB), the loop channel (4096), the stream channel (1024) and the mailbox (64) are new tests that fill them.
* **`eng:mem` is `ctrl:mem`** (stepped by the TUI loop under `-v`, now every 10 s instead of 2 s). A headless run does not step it into the graph; it writes `memory.json` every 10 s and once more when it ends, which is what `aibus doctor --session <id>` prints. A TUI session has no session directory yet (C1.2 notes), so `doctor --session` has nothing to read for one.
* **First frame cold** includes opening a fresh SQLite index, as the table in 08 section 1 says, although section 8 says SQLite opens lazily. In a debug build that open dominates (the bundled C is unoptimised), so the test uses a looser ceiling there and the workflow runs it with `--release`.
