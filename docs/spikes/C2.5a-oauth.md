# C2.5a: OAuth

Notes for whoever adds the first real OAuth provider. The user-facing part is the OAuth section of `docs/PROVIDERS.md`.

* The config is `auth = { oauth = true }` (a field on `config::Auth`, not an `AuthMethod` enum, since the config has none). `key_ref()` still says `keyring:aibus/<name>` for it: the tokens are one JSON value in the entry a key would use.
* `CredentialStore::resolve` branches on `auth.oauth` before the 60 second cache, because a token has its own expiry. It refreshes when 60 seconds or less are left, keeps the old refresh token if the new response has none, and writes the result back before returning. Every failure is `CredentialError::OAuth`, which is `AibusError::Auth`, exit 4.
* The credential comes out with `AuthMethodKind::OAuth`. Both provider crates already send a non-key kind as `Authorization: Bearer`; the Anthropic header match got `| OAuth` on its bearer arm and nothing else changed there.
* `OAuthFlow` (login and refresh) is a sync trait in `aibus-core`; the real one is meant to live in the binary next to `OsKeychain`. `Io.oauth` is `None` in the shipped binary and in the TUI, and no factory lists `OAuth`, so `--oauth` is refused until a provider does. Adding one is: list `AuthMethodKind::OAuth` in its factory, write the flow, pass it in `commands::account`.
* The redactor holds the access token under the account name and the refresh token under `<name>:refresh`; `remove` drops both.
* Not covered: nothing here talks to a real authorisation server, so the endpoints, PKCE and scopes are untested. A refresh is not guarded against two requests refreshing at once.
